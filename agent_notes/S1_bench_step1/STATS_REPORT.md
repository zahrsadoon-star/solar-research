## Leakage and imbalance

Source inspection finds trailing history and current-origin features only; future target calendar values are known. Training excludes labels reaching the test-month start. Automated future perturbation tests cover both horizons; real-data tests check exported labels, monthly training-target boundaries, both classes in each train/test fold, and training-only scaler moments in the actual LR pipeline. All scaled algorithms place StandardScaler inside their pipeline. Metering for the completed origin hour is assumed available at issuance; this operational assumption is not independently verified.

The random split is descriptive and allows future observations relative to a test origin; it is not prospective evidence. MLP uses internal random early-stopping validation within the outer training period; that does not expose outer test data, but its internal validation is not chronological. No class weighting, resampling or threshold tuning is applied. Monthly test outage counts/shares are saved in results. Accuracy alone is unsuitable for the imbalanced KR case; Brier, AUC, F1 and the no-outage reference are necessary context. Pooled scores do not establish calibration or minority-class usefulness across seasons.

## Statistical protocol review (not executed)

The requested paired moving-block bootstrap must use the same contiguous 24-hour index draws for both algorithms and AUC, and the same draws across metrics. Preserve temporal ordering; do not independently resample forecasts. Single-class AUC resamples need explicit handling. Daily blocks do not establish robustness to longer or seasonal dependence.

DM should use centered Brier differences and Bartlett-weighted Newey-West long-run variance, with lag h-1+24, followed by the Harvey-Leybourne-Newbold correction using forecast horizon h (not HAC lag). Handle zero loss differences without division by zero. The stationarity/weak-dependence approximation is questionable for pooled seasonal data and changing monthly fitted models; it cannot be proven by the requested calculation.

The proposed family is 15 top-six pairs plus 6 reference pairs per site/horizon (21 tests), with Holm within each case. This does not control multiplicity over all cases. Top-six selection using the same test outcomes makes interpretation exploratory; ordinary pairwise intervals are not simultaneous. A top group based on non-rejection or an interval covering zero means insufficient evidence of a difference, not equivalence or a proven tie. Existing historical significance.csv is not validated under this requested protocol.

The spec says significance.py reads only predictions.csv.gz but selects top six from benchmark_results.csv. Before implementation, resolve whether to allow that ranking input or recompute the same Brier ranking from predictions after preservation passes.
